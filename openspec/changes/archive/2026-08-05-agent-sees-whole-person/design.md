## Context

`exportScopedSnapshot` כותבת `people.json` — עותק לקריאה בלבד שהסוכן עובד עליו, חתוך לראות המשתמש. המבנה נבנה ידנית, שדה-שדה, וזו גם החוזקה שלו (הסוכן מקבל עברית מובנית ולא סכימת Prisma) וגם הכשל: **כל שדה שלא נכתב במפורש פשוט אינו קיים**, ואין דבר שיאמר זאת.

מה שנמצא בפועל, בבדיקה מול הבסיס:

```
בכרטיס האדם                 בתמונת המצב
─────────────                ────────────
שם פרטי / שם משפחה     →     שם (מאוחד)          ✔
תאריך לידה             →     — חסר —             ✘   34 מתוך 41 אנשים
גיל (נגזר)             →     — חסר —             ✘
תאריך גיוס             →     תאריך_גיוס          ✔
תאריך הצבה             →     תאריך_הצבה_ביחידה   ✔
סטטוס העסקה            →     סטטוס               ✔
תאריך סיום שירות       →     סיום_שירות          ✔
שדות שנוספו            →     פרטים_נוספים        ~   רק מה שמולא
```

## Goals / Non-Goals

**Goals:**
- הסוכן יידע כל מה שכרטיס האדם יודע.
- הסוכן יידע אילו שדות **קיימים**, לא רק אילו מולאו.
- מוסכמת תאריך אחת בקובץ כולו.
- בדיקה שתיכשל כשהפער ייפתח שוב.

**Non-Goals:**
- שינוי הנתונים עצמם. שום שדה אינו חסר בבסיס.
- חשיפת התמונה, הנתיבים בדיסק או מזהים פנימיים.
- החלפת המבנה הידני בסריאליזציה אוטומטית של Prisma — ראו למטה.
- הרחבת ההיקף: החיתוך לפי ראות המשתמש נשאר בדיוק כפי שהוא.

## Decisions

### הגיל מיוצא, ואינו מושאר לחישוב הסוכן

תאריך לידה לבדו מספיק כדי לענות «מי חוגג החודש». הוא **אינו** מספיק כדי לענות «מי מעל גיל 40» באותה תשובה שהכרטיס נותן, כי `ageFromBirthDate` סופרת חודשים שלמים ומטפלת בקצה החודש בדרך מסוימת. סוכן שיחשב גיל בעצמו יגיע לתשובה שנכונה ±יום — ותיראה כמו סתירה מול הכרטיס.

לכן שניהם נכתבים: התאריך לחישובים, והגיל **מאותה פונקציה בדיוק** שהכרטיס משתמש בה.

### הגדרות השדות נכתבות בנפרד מן הערכים

```jsonc
// people.json — ערכים, כפי שהם היום
"פרטים_נוספים": { "השכלה": "…", "תפקיד": "חוקר" }

// schema.json — מה קיים בכלל
[ { "שדה": "עיר מגורים", "סוג": "טקסט" },
  { "שדה": "מצב משפחתי", "סוג": "בחירה", "אפשרויות": [...] }, … ]
```

היום לאדם שנבדק היו 3 ערכים מתוך 9 שדות מוגדרים. לסוכן אין דרך לדעת שקיים שדה «עיר מגורים», ולכן לשאלה «מי גר בתל אביב» הוא עונה שאין שדה כזה — אותה תשובה בדיוק שהוא ייתן על שדה שבאמת אינו קיים. **שתי שאלות שונות מקבלות תשובה זהה, וזו התקלה.**

עם `schema.json` הוא יכול לענות את התשובה הנכונה: השדה קיים ואיש לא מילא אותו.

**נדחה:** להשלים כל שדה חסר כ-`null` בתוך `פרטים_נוספים`. זה היה מנפח כל אדם ברשימת שדות ריקים, ועדיין לא היה אומר מה הסוג ומה האפשרויות של שדה בחירה.

### תאריכים בשדות מותאמים — ISO, כמו כל השאר

הערה שכבר כתובה בקובץ אומרת: *«ISO on purpose: this is a machine interface … a snapshot the agent reasons over must have no reading convention to get wrong»*. ערכי שדה מסוג DATE שוברים אותה: הם נשמרים כפי שהוזנו — `dd/mm/yyyy` — ומיוצאים גלמיים.

היום זה סמוי, כי אין כרגע אף שדה מותאם מסוג תאריך במערכת. זו בדיוק הסיבה לתקן עכשיו: התקלה תופיע ביום שבו אדמין יוסיף שדה תאריך, והיא תופיע כתשובה שקטה ושגויה — `03/08` שנקרא כ-3 באוגוסט או כ-8 במרץ — ולא כשגיאה.

### הבדיקה משווה בין שני מקורות אמת, ולא בודקת שדה אחד

הליקוי אינו «תאריך לידה חסר». הליקוי הוא ש**כרטיס האדם ותמונת המצב מתארים את אותו דבר בשתי רשימות שאיש לא השווה**. בדיקה שתאמת שתאריך לידה קיים תעבור לנצח ולא תתפוס את השדה הבא שיישכח.

לכן הבדיקה נכתבת כהשוואה: שדות הליבה נקראים מן המקום שבו הכרטיס מגדיר אותם, ומול כל אחד נדרש ייצוג בתמונת המצב. שדה ליבה חדש שיתווסף לכרטיס ולא לתמונת המצב — ייכשל.

**מגבלה שנרשמת ולא מוסתרת:** ההתאמה היא לפי טבלה מוצהרת (שם ליבה → מפתח בתמונת המצב), כי השמות אינם זהים ולא צריכים להיות. הטבלה עצמה יכולה להישכח — אבל שכחה שלה מפילה את הבדיקה, ולא משתיקה אותה.

### מה שלא נעשה: סריאליזציה אוטומטית

מפתה להחליף את המיפוי הידני ב-«כתוב את כל השדות». זה היה מונע את התקלה הזו ומכניס גרועה ממנה: כל עמודה חדשה בבסיס הייתה זולגת אל הסוכן בלי החלטה — נתיבי קבצים, מזהים פנימיים, גיבובי סיסמאות בטבלאות שכנות. המבנה הידני הוא **החלטה מה לחשוף**, וזה שווה את המחיר. המחיר משולם בבדיקה, לא בוויתור על השליטה.

## Risks / Trade-offs

- **תאריך לידה הוא נתון אישי** → הוא כבר מוצג בכרטיס לכל מי שרואה את האדם, ותמונת המצב חתוכה לאותה ראות בדיוק. אין הרחבה של מי רואה מה.
- **`schema.json` מגדיל את התמונה** → תשע שורות. זניח מול `people.json`.
- **טבלת ההתאמה בבדיקה עלולה להישכח** → מוצהר למעלה; שכחה מפילה, לא משתיקה.
- **הסוכן יראה גיל מחושב** ועלול לצטט אותו כעובדה שנשמרה. מקובל: זה בדיוק מה שהכרטיס מציג.

## Migration Plan

1. אין מיגרציה ואין שינוי סכימה — הנתון קיים ולא נמסר.
2. הפריסה היא הפריסה הרגילה; תמונת המצב נבנית מחדש בכל ריצה, כך שהריצה הראשונה אחרי הפריסה כבר רואה את השדות.
3. חזרה לאחור: היפוך השינוי ב-`agent-snapshot.ts`. אין מצב שמור להתחשב בו.
