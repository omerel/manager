## Why

הסוכן אינו רואה את כל מי שהשואל רואה. שתי קריאות של ״מה המשתמש הזה רואה״ התפצלו בשקט:

```
people.ts:103          isAdmin ? { OR: [{ teamId: { in: … } }, { teamId: null }] } : { teamId: { in: … } }
agent-snapshot.ts:59   { teamId: { in: teamIds } }
```

אדם ללא שיוך למסגרת מופיע לאדמין בעמוד האנשים ואינו קיים עבור הסוכן כלל. במסד הנוכחי מדובר ב-**6 מתוך 13 אנשים**. אדמין ששואל עליהם מקבל ״לא נמצא״, ולא ״אין להם מסגרת״.

**הראיה שההשמטה לא הייתה מכוונת:** ‏`pathOf` באותו קובץ (שורה 84) מטפל במפורש ב-`teamId === null` ומחזיר «ללא שיוך» — ערך שהשאילתה בשורה 59 לא תספק לו לעולם. הפורמטר נכתב לאנשים שהשאילתה חוסמת; זהו ענף מת שמעיד על הכוונה המקורית.

**והמפרט נוטה נגד ההתנהגות הקיימת.** ‏`agent-qa-chat` דורש תשובות ״scoped to the user's visibility״, ובדרישה נפרדת קובע במפורש שאדם שחסר לו נתון ״**יידווח כחסר ולא יושמט בשקט מהספירה**״. השמטה שקטה של האדם עצמו היא אותה תקלה, חמורה יותר.

**ולמה אף בדיקה לא תפסה.** הדרישה ״הכרטיס ונתוני הסוכן נבדקים זה מול זה״ קיימת ועובדת — אבל היא משווה **שדות**: *"a comparison of the two, not an assertion about any particular field"*. הסחיפה כאן אינה בעמודה אלא בשורה. הערובה היא ברמת השדה; הפער ברמת האוכלוסייה. הבדיקה לא יכלה לתפוס אותו, ולא משום שנכתבה רע.

## What Changes

- **הסנפשוט נבנה מאותה הגדרת נראוּת שעמוד האנשים משתמש בה.** אדם שהשואל רשאי לראות נכנס לסנפשוט, לרבות אדם ללא מסגרת כשהשואל אדמין. הענף «ללא שיוך» ב-`pathOf` מפסיק להיות מת ומתחיל לתאר שורות אמיתיות.
- **ציר שני לבדיקת ההשוואה:** לא רק ״כל שדה בכרטיס קיים אצל הסוכן״ אלא גם ״כל **אדם** שהמשתמש רואה קיים אצל הסוכן״. זו הבדיקה שהייתה תופסת את התקלה הזו, והיא שתתפוס את הבאה.
- **הגדרה אחת, שני צרכנים.** הכלל ״אילו אנשים המשתמש הזה רואה״ ייאמר במקום אחד ויקרא משם גם עמוד האנשים וגם הסנפשוט, כדי שלא תהיה שוב אפשרות שהשניים יחלקו.

### מה זה משנה בפועל

מנוע החוקים משתמש באותו סנפשוט (שני אתרי קריאה ב-`rules-engine.ts`), ולכן **חוק מתוזמן שסורק אנשים מדלג היום על הלא-משויכים בשקט**. אחרי השינוי הם ייכללו. זו התנהגות רצויה, אבל היא שינוי בתוצאה של חוקים קיימים — ולכן זה שינוי מפרט ולא תיקון שקט.

### מה במפורש אינו משתנה

- **מנהל או משא״ן אינם מושפעים.** עבורם `getVisiblePeople` ממילא אינו כולל לא-משויכים, ולכן הסנפשוט שלהם זהה למה שהיה. השינוי נוגע לאדמין בלבד.
- **ציר השאילתות** (`queries.json`) נשאר כפי שהוא — הוא עוקב אחר יחסי שאילתה ולא אחר עץ הארגון, וזה מתועד כבר היום כציר נפרד במכוון.
- **אין שינוי במה שהסוכן רשאי לעשות** — קריאה בלבד, כפי שהיה.

## Capabilities

### New Capabilities

אין. זהו תיקון של התנהגות שכבר מוגדרת, והידוק הערובה שהייתה אמורה לשמור עליה.

### Modified Capabilities

- `agent-qa-chat`: ״שאלות ותשובות על נתוני קריירה״ מבהיר שהיקף הנתונים הוא בדיוק אוכלוסיית האנשים שהשואל רשאי לראות, ואדם ללא מסגרת אינו יוצא דופן; ו״הכרטיס ונתוני הסוכן נבדקים זה מול זה״ מקבל ציר שני — אוכלוסייה, לצד השדות.

## Impact

**קוד** — ‏`lib/agent-snapshot.ts` (השאילתה), ‏`lib/people.ts` (הוצאת כלל הנראוּת לנקודה אחת), ‏`scripts/verify-agent-snapshot.ts` (הציר השני).

**תלוי ב-`verify-suite-fixtures`** ברמת הנוחות ולא ברמת הנכונות: `verify-agent-snapshot` נופל כרגע מסיבה אחרת לגמרי — הוא בוחר אדם שרירותי מהמסד — ולכן קשה לקרוא ממנו תוצאה. אפשר לעבוד בשני הסדרים, אבל תיקון הפיקסטורות תחילה עושה את הריצה כאן קריאה.

**אין מיגרציה ואין סכמה.** הסנפשוט נבנה בכל קריאה לתיקייה זמנית ונמחק אחריה.
