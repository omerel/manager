## Context

`framework-commander` הוסיף למשתמש שדה אחד: המסגרת שבפיקודו, ייחודית למסגרת ומותנית בהרשאה. שם היא הייתה תווית — עובדה שנרשמת ונקראת. כאן היא הופכת למנוע: היא קובעת מי רשאי לשאול, מי חייב לענות, ומי רואה מה.

העץ מרובד בקפדנות. `updateOrgNode` אוכף `PARENT_KIND` — אב של צוות הוא מדור, אב של מדור הוא תחום, אב של תחום הוא מרכז, ומרכז הוא שורש. אין דילוגים, ולכן «דרגה אחת מתחת» היא הגדרה חדה ולא פרשנות.

## Goals / Non-Goals

**Goals:**
- שאילתא שנשלחת לדרגה אחת מתחת, ורשימה שמראה בבירור מי הגיב ומי לא.
- תאריך יעד שניתן להזזה, בלי שהמצב יסתבך.
- כלל ראייה יחיד בלי חריגים: רק השואל והנשאל.
- מסגרת בלי מפקד — מצב גלוי, לא כשל שקט.

**Non-Goals:**
- שאילתא לעומק (מרכז ישירות לצוותים) או לרוחב (בין מדורים).
- שרשור דיון: השאילתא היא שאלה ותשובה, לא צ׳אט.
- קבצים מצורפים, שאילתות חוזרות, או תבניות.
- היסטוריית גרסאות של תשובה — נשמרת התשובה הנוכחית ומועד עדכונה.

## Decisions

### שני הקצוות עוגנים במסגרת, לא באדם

```prisma
model Query {
  senderNodeId  String   // המסגרת ששאלה
  authorId      String?  // מי כתב בפועל (SetNull)
  title, body, dueDate
}
model QueryTarget {
  queryId, nodeId        // מסגרת בת אחת
  answer      String?    // null = טרם הגיב
  answeredById String?   // מי כתב בפועל
  answeredAt, updatedAt, remindedAt
}
```

ההכרעה הזו נגזרת מדרישה שכבר נאמרה: «במידה ואין יוזר שמוגדר כמפקד המסגרת, זה יסומן לשולח». שאילתא שיכולה להיות מופנית למסגרת **שאין בה איש** מופנית, מעצם הגדרתה, למסגרת. האדם הוא רק מי שבמקרה עונה.

מכאן נופלים לבד כל המקרים הקשים: מפקד שהוחלף באמצע, מפקד שמונה אחרי השליחה, מפקד שהפיקוד הוסר ממנו. בכולם התשובה זהה — **מי שמפקד עכשיו, עונה עכשיו**.

אותו היגיון חל על קצה השליחה. אילו השאילתא הייתה שייכת לאדם, החלפת מפקד תחום הייתה מייתמת כל שאילתא שבאוויר ואיש לא היה יכול לגבות את התשובות. `authorId` הוא קרדיט, לא בעלות.

### הסטטוס נגזר משתי עובדות ואינו נשמר

```
   שמור:  dueDate      התאריך שנמסר לנמענים
          closedAt     השואל סיים מוקדם

   נגזר:  פתוחה ⟺ closedAt ריק  וגם  היום ≤ dueDate

   ┌─────────┐  התאריך עבר / השואל סגר  ┌─────────┐
   │  פתוחה  │ ────────────────────────▶│  סגורה  │
   │         │◀──────────────────────── │         │
   └─────────┘  הארכה / פתיחה מחדש      └─────────┘
```

דגל `closed` בוליאני היה משכפל את מה שהתאריך כבר אומר, ונסחף בכל עריכת תאריך. `closedAt` אינו כפילות אלא **עובדה שהתאריך אינו יכול לבטא**: השואל החליט שדי. זה ההבדל שמכשיר את שמירתו.

**הגרסה הראשונה סגרה שאילתא בדחיפת `dueDate` אל העבר.** לא נדרשה עמודה — והיא שיקרה לכל מי שקרא אחר כך: התאריך שנמסר לנמענים הופך בשקט לאתמול. וגרוע מכך, כדי לא לסגור בטעות היא דרשה תיבת אישור, ובלעדיה זרקה שגיאה — כך שהקלדת תאריך שגוי נראתה כמו קריסה. **אישור מקומו לפני הפעולה, לא בתוכה.**

לכן: תאריך עבר נדחה כהודעת ולידציה רגילה ולא מוצע כלל בלוח השנה, והסגירה היא כפתור נפרד עם `window.confirm` שנוקב במספרים. פתיחה מחדש קיימת משום שסגירה בלי ביטול היא מלכודת — השואל מחליט על סמך תשובות חלקיות, ואסור שטעות תהיה סופית. פתיחה מחדש מחזירה את מה שהתאריך אומר, ואינה מחיה שאילתא שתאריכה חלף בינתיים.

**התאריך כולל.** `31/12` פירושו עד סוף אותו יום. אותה נקודה שנקבעה ב-`israeli-date-format`: התאריך הוא יום, לא רגע.

### התוכן ננעל, התאריך לא

```
   0 תשובות   →  כותרת · תוכן · תאריך    ניתנים לעריכה
   ≥1 תשובה   →  תאריך בלבד
```

תוכן שנערך אחרי שהתקבלו תשובות מייצר את המצב המבלבל ביותר האפשרי: תשובות לשאלה שכבר לא מופיעה על המסך. התאריך, לעומת זאת, אינו משנה את מה שנשאל — רק עד מתי.

### כלל ראייה יחיד, בלי חריגים

> שאילתא נראית לשתי מסגרות בלבד: זו ששאלה וזו שנשאלה.

מדור א׳ אינו רואה את תשובת מדור ב׳. המרכז אינו רואה את מה שהתחום שאל את מדוריו. **האדמין אינו רואה דבר** — באותה תקדים שבו דף החוקים פרטי גם ממנו.

הכלל מנוסח כמשפט אחד במפרט דווקא משום שהוא יעמוד בלחץ: מתישהו מישהו יבקש «דוח מנהלים» שחוצה אותו. עדיף שזה יהיה שינוי מוצהר מאשר סדק.

### מה שהתגלה ולכן אינו צריך שמירה: אין דליפת מידע

חשש סביר הוא שתשובה תכיל עובדות על אנשים שהשואל אינו רשאי לראות. היא לא יכולה, וזו תוצאה של מה שכבר נבנה ולא כלל חדש:

```
ראות = ⋃ subtree(g) לכל הרשאה g

X נראה  ⟹  X ∈ subtree(g) עבור הרשאה g כלשהי
        ⟹  g הוא אב-או-עצמו של X
        ⟹  subtree(X) ⊆ subtree(g) ⊆ ראות
```

פיקוד מחייב ראייה, וראיית צומת פירושה ראיית כל תת-העץ שלו. **מפקד רואה תמיד את כל מה שמתחת למה שבפיקודו** — כך שכל תשובה שכפיף יכול לכתוב עוסקת באנשים שהשואל רשאי לקרוא ישירות ממילא.

**הסתייגות שנרשמת ולא מוסתרת:** התכונה תקפה בשעת המינוי. העברת מסגרת בעץ יכולה להוציא מפקד מטווח הראייה — חור שהושאר במכוון ב-`framework-commander`, מסומן ולא חסום. היום הוא קוסמטי; משנשלחות בו שאילתות הוא נושא תוכן, ושווה לשקול לסגור אותו.

### שליחת הדואר אחרי התשובה

`sendReport` מריצה תהליך פייתון לכל נמען. מרכז עם שמונה תחומים פירושו שמונה תהליכים בתוך פעולת שרת אחת. השליחה נעשית ב-`after()` — הדפוס שכבר קיים ב-`jobs.ts` — כך שהטופס חוזר מיד.

המחיר מוצהר: השולח לא יידע באותו רגע שכתובת אחת נכשלה. לכן תוצאת השליחה נרשמת על שורת הנמען ונראית ברשימה, במקום להיעלם.

**עדכון תאריך אינו שולח מייל מעצמו** — הוא מציע את אותה תזכורת ידנית שכבר קיימת. מסלול התראה אחד, לא שניים.

### תיוג אדם: המזהה הוא האמת, השם נוחות

```
   @[דנה כהן](cmsf6i3vf00026pzur2lpi31a)
        ↑                  ↑
    התווית בשעת         המזהה — ההפניה עצמה
     הכתיבה
```

שאילתות הן כמעט תמיד על אנשים, ולכן הטקסט צריך להצביע עליהם ולא רק להזכיר את שמם. התיוג נשמר **בתוך המשפט** ולא בטבלת קשר, כי לתיוג יש מיקום במשפט וטבלה צדדית הייתה צריכה להמציא אותו מחדש.

השם ברינדור נפתר מחדש מן המזהה: אדם ששונה שמו אחרי שתויג יופיע בשמו הנוכחי, ולא בשם שהוקפא בטקסט. התווית השמורה משמשת רק כשהאדם כבר אינו קיים — המקרה היחיד שבו הטקסט הישן עדיף על כלום.

**שלוש צורות רינדור, וכל אחת מכוונת:** אדם שהקורא רשאי לראות — קישור שנפתח בלשונית חדשה; אדם שאינו רשאי — השם כטקסט רגיל, כי עמוד האיש היה מחזיר לו «לא נמצא» וקישור שמוביל לשום מקום גרוע מאין קישור; אדם שנמחק — התווית השמורה.

בכל מקום שבו הטקסט **נקרא ולא מרונדר** — המייל, וגם תמונת המצב של הסוכן — התיוג משוטח ל-`@שם`. אחרת ההודעה במייל הייתה מגיעה כ-`@[דנה כהן](cmsf…)`.

### «חדש מאז שהסתכלתי» נשמר, ואינו נגזר

המונה בכותרת נושא שתי משמעויות שונות על אייקון אחד, והן אינן סימטריות:

```
   ממתין לתשובתי   → נגזר   (שאילתא פתוחה בלי תשובה)
   תשובה שלא קראתי → נשמר   (seenBySender על שורת הנמען)
```

ההבדל אינו שרירותי. «פתוחה ובלי תשובה» היא עובדה על הנתונים. «חדש מאז שהסתכלתי» היא עובדה על **הקורא**, ושום חותמת זמן על התשובה אינה יכולה לספק אותה. לכן דווקא כאן שמירה היא הדבר הנכון — בניגוד ל-`closed`, שהיה משכפל את מה שהתאריך כבר אומר.

הסימון מתאפס בכל תשובה, כולל תיקון: תשובה ששונתה היא חדשות בדיוק כמו תשובה ראשונה.

**הניקוי נעשה ב-`after()` ולא בזמן הרינדור.** שינוי מצב בתוך רינדור היה מנקה את המונה על prefetch — לפני שאיש הסתכל על משהו. המשתמש רואה את הסימון בביקור הזה, והוא נעלם בבא אחריו.

### מחיקה: המפל כבר קיים

מחיקת שאילתא מוחקת את עותקי הנשאלים — לא בקוד, אלא ב-`onDelete: Cascade` שכבר הוגדר. אין מחיקה שנייה לזכור ואין חלון שבו שורת נמען שורדת את השאלה שהיא שייכת לה. האישור נוקב בכמה תשובות עומדות להימחק, כי זה מה שבאמת אובד.

### היקף הסוכן: ציר שני

`exportScopedSnapshot` חותכת היום לפי ראות הקריירה. שאילתות אינן נתוני קריירה, ולכן הן נחתכות אחרת: **מה ששאלתי ומה שנשאלתי**, בתוכן מלא. זהו הציר השני הראשון בתמונת המצב, ומוטב לקרוא לו בשמו בקוד — לא להרחיב את `Visibility` כדי שיכיל אותו.

## Risks / Trade-offs

- **מסגרת בלי מפקד תיראה כתקלה** → מוצגת כשורה מפורשת («אין מפקד למסגרת») עם קישור לעמוד ההרשאות, כלומר כמשימה ולא כשגיאה.
- **`after()` מסתיר כישלון שליחה** → נרשם על שורת הנמען ונראה ברשימה.
- **מונה גלובלי בכותרת** = שאילתה נוספת בכל טעינת עמוד לכל משתמש. זולה, אך זהו התג הגלובלי הראשון באפליקציה.
- **הכלל «רק השואל רואה» ילחץ** → משפט אחד במפרט, כדי שפרצה תהיה החלטה.
- **מסגרת בלי בנות** (מדור בלי צוותים) → השליחה נדחית בהודעה, במקום ליצור שאילתא ריקה שאיש לא יקבל.

## Migration Plan

1. מיגרציה: `Query`, `QueryTarget`, מפתחות זרים ל-`OrgNode` (מחיקת מסגרת מוחקת את שורות היעד שלה), ואינדקס על `(queryId, nodeId)`.
2. אין נתונים להעביר. משתמשים קיימים רואים עמוד ריק, וזה המצב הנכון.
3. חזרה לאחור: הסרת שתי הטבלאות ופריט הניווט. שום דבר קיים אינו תלוי בהן.
